## Configuration files

- **Velocity:** `plugins/librelogin/config.yml` and `messages.yml`.
- **Paper:** usually `plugins/LibreLogin/config.yml` and `messages.yml`.

The comments generated by your installed revision are authoritative. Preserve YAML indentation and use `#` for comments, not `//`. Merge the following snippets into their existing sections.

> **Restart required:** Stop the instance before changing databases, worlds/backends, aliases or integrations, then restart. Reloading configuration does not necessarily rebuild those components.

## Limbo and lobby

```yaml
limbo:
  - auth
lobby:
  root:
    - lobby
remember-last-server: false
fallback: false
```

Velocity uses names registered under `[servers]`; Paper uses world names, with all destinations under `root`. Forced hosts can have their own lobby group. Use `§` instead of dots in those keys, as explained by the generated comments.

`remember-last-server: true` reuses the last destination when available. `fallback: true` lets the proxy try another lobby after a backend failure; it does not authorize players who still need to complete login/registration or 2FA.

## Database

The initial `database.type` is `librelogin-sqlite`. Multiple proxies need a shared database rather than independent SQLite files.

### MariaDB

Example in `config.yml`:

```yaml
database:
  type: librelogin-mysql
  properties:
    mysql:
      database: librelogin
      host: db.example.net
      port: 3306
      user: librelogin
      password: "REPLACE_WITH_YOUR_PASSWORD"
      jdbc-url: "jdbc:mariadb://%host%:%port%/%database%?autoReconnect=true&zeroDateTimeBehavior=convertToNull&sslMode=verify-full"
```

### Official MySQL

Use the same `librelogin-mysql` type and `mysql` section; select the official driver with this URL:

```yaml
jdbc-url: "jdbc:mysql://%host%:%port%/%database%?sslMode=VERIFY_IDENTITY"
```

### PostgreSQL

```yaml
database:
  type: librelogin-postgresql
  properties:
    postgresql:
      database: librelogin
      host: db.example.net
      port: 5432
      user: librelogin
      password: "REPLACE_WITH_YOUR_PASSWORD"
      jdbc-url: "jdbc:postgresql://%host%:%port%/%database%?sslmode=verify-full"
```

Keep username and password in their separate fields. Upgrades preserve an existing `jdbc-url`, so review its TLS mode explicitly.

### TLS modes

| Driver / URL | Full verification | Disable TLS |
|---|---|---|
| MariaDB, `jdbc:mariadb://` | `sslMode=verify-full` | `sslMode=disable` |
| MySQL, `jdbc:mysql://` | `sslMode=VERIFY_IDENTITY` | `sslMode=DISABLED` |
| PostgreSQL, `jdbc:postgresql://` | `sslmode=verify-full` | `sslmode=disable` |

**`sslMode` is a URL parameter, not a YAML boolean.** Use the driver-specific values above rather than `off` or `false`. For a private CA, MariaDB supports `serverSslCert` and PostgreSQL supports `sslrootcert`; configure the driver's certificate settings to resolve certificate errors.

> **Unencrypted connections:** The plugin allows non-TLS URLs and warns for non-loopback destinations. Credentials and password hashes then travel in clear text. `localhost`, `127.0.0.1` and `::1` only suppress that warning; they do not automatically change the URL's TLS mode.

## Accounts and sessions

```yaml
auto-register: false
profile-conflict-resolution-strategy: BLOCK
session-timeout: 0
minimum-password-length: 8
max-login-attempts: 5
milliseconds-to-refresh-login-attempts: 60000
seconds-to-authorize: 120
login-log-alias: true
```

| Setting | Meaning |
|---|---|
| `auto-register: false` | A premium name alone does not enable autologin for a new offline account. Existing premium-mode accounts still require a valid Mojang session. |
| `session-timeout: 0` | Disables IP-based sessions. A positive value lets registered accounts reuse a recent authentication from the same IP; sharing an IP does not prove a person's identity. |
| `login-log-alias: false` | Releases `/log` for Carpet or another plugin after a restart, keeping `/login` and `/l`. |
| `profile-conflict-resolution-strategy: BLOCK` | Keeps identity conflicts blocked for an administrator to resolve. `OVERWRITE` deletes the conflicting offline profile's data. |

Do not change `new-uuid-creator` as a login workaround. It affects the identity assigned to new accounts and must be planned alongside player and world data.

## Two-factor authentication

```yaml
totp:
  enabled: true
  qr-enabled: false
  label: "My Server"
  delay: 1000
```

**`qr-enabled: false` selects manual secret/URI setup.** When it is `true`, Velocity can also send a map through a compatible integration; Paper uses the manual route.

> **Existing factors:** `enabled: false` does not remove saved secrets or allow accounts to skip 2FA. See [setup and recovery](Commands-and-2FA.md#two-factor-recovery).

## Messages

Example in `messages.yml`:

```yaml
prefix: "&6[My Server] &r"
prompt-login:
  - "[center]&ePlease log in"
  - "&f/login <password>"
```

Use `prefix: ""` to remove the prefix. Message values support lists of lines, `\n`, legacy `&` colors and MiniMessage. The prefix is excluded from titles, action bars and email templates.

After editing messages, run `/librelogin reload messages` or restart. Title, action-bar and bossbar settings are controlled in `config.yml`.
